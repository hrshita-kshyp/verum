What it does

Five steps, and it will skip any of them rather than guess.

01
Research
Reads a company's own site, its filings and recent coverage. Never a data broker, never a scraped list.
02
Verify
Eleven checks: a named decision-maker, a route to them published by the company itself, a dated reason to write now, nothing that contradicts what's being claimed.
03
Write
A short email built only from sourced facts, phrased as a question rather than an assertion about a problem no one confirmed.
04
Send
Inside the recipient's own business hours, spaced apart, inside that country's own consent rules — five jurisdictions handled differently, on purpose.
05
Log
Every decision is recorded, including the four in five leads it declined to send — so the bar it holds never quietly slips.
How it runs unattended

It forgets everything between runs, on purpose.

Each scheduled run is a disposable cloud session with no memory of its own. Everything it knows about what's already been sent, held or refused lives on one git branch — pulled in at the start of a run, pushed back before the session is destroyed.

Working principles

The rules it can't argue itself out of.

✓
A fact needs a source
Every claim in a sent email traces to a URL in the log. No source, no sentence.
✓
An address is never guessed
If a company hides its email, the lead waits for a person. It is never pattern-guessed from a name.
✓
One bounce throttles everything
A single bad address automatically drops the day's send limit — no one has to notice and intervene.
✓
Replies are read, never answered
It classifies an inbound reply and drafts a response. A person decides whether it actually goes out.
✓
Zero is a good result
A day with nothing sent means nothing cleared the bar — not that the bar moved to make room.
